## 1. 검토한 생성 규칙 및 데이터 구조

`generate_revision2.py`는 revision의 주문·주문상세와 일별 수요를 상속하고, 주문상세에 `serving_temperature`를 추가합니다. 온도 선택 가능 메뉴는 메뉴 ID를 나누지 않고 상세 단위로 HOT/ICE를 선택합니다. 적용한 합성 가중치는 `p(HOT)=clip(1/(1+exp((avg_temp_c-16)/5)), 0.10, 0.95)`이며, 이는 실제 관측 인과관계가 아닙니다.

시험 일정은 revision의 `generation_rules.json`에서 상속됩니다. revision 생성 규칙은 이벤트별 시작 전 14일 상승, 시험 중 유지, 종료 후 14일 선형 감소를 설정하고, 동시에 활성인 이벤트는 가장 큰 효과와 나머지 효과의 25%를 합산해 22% 상한을 적용합니다. 따라서 데이터상 시험 효과에는 여러 학교의 기여가 합쳐질 수 있습니다.

## 4. 일별 주문 수 정합성 실패

실제 주문 행을 날짜별로 다시 집계하면 31,753건이며 최대 일 주문 수는 81건입니다. 그러나 revision2의 `daily_sales.csv`에서 `order_count`는 669일 모두 0이고 총합도 0입니다. 이는 `orders.csv` 날짜별 주문 집계와 일치하지 않습니다. `daily_sales.csv`의 `average_ticket`도 전 날짜에서 `actual_sales`와 동일해 일평균 주문금액으로 쓸 수 없습니다. 매출 합계가 일치하더라도 이 두 필드는 통과가 아닙니다.

이는 revision2 생성 코드가 revision의 `daily_sales.csv`를 복사하면서 해당 필드 값을 그대로 유지한 결과입니다. 이번 감사에서는 사용자 지시대로 기존 파일을 수정하지 않았습니다. 이 데이터 구조 오류는 후속 수정 전까지 일별 주문량 기반 시험 효과 검증과 평균 객단가 해석을 제한합니다.
